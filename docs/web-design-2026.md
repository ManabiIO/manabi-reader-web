## Decisions

Use ordinary opaque browser surfaces, system UI fonts with Windows/Linux/Japanese fallbacks, existing semantic Manabi colors and restrained eight-pixel action corners. Keep icon-only search, collections and overflow where their functions are familiar and names remain accessible; make Import a visible text action when space permits. Hover, expanded, pressed and keyboard focus states remain distinct.

Tablet and desktop share the same flat navigation rail from 768 px. The toolbar wraps naturally when search needs another row. Phone controls retain 44 px targets. Remove the floating rail frame and blurred library header, reducing layers between navigation and content. Keep the reader's Japanese typography and vertical layout independent of shell fonts.

Empty states identify missing books and offer existing actions. Remove the large empty-library card and the decorative “for Web” suffix; add no promotional copy, artwork or new data features. Use natural “Import files” and “Import folder” labels. Keep the file action primary, and group backup/migration imports in a native keyboard-accessible “Other import options” disclosure. All connected-library choices remain visible. Retain useful import and connection guidance. Editor's Picks retains its loading, empty, error and retry behavior. There is no separate feed-management screen in the current web navigation, so none was invented.

Browser overrides load from `RuntimeProvider.web.tsx`. The native runtime and Android embedded reader's shared base styles remain unchanged. Persistence, imports, account connections, reading controls and lookup ownership are untouched.

The follow-up visual review found that the embedded reader's accessible `div` dialogs were not covered by the native `dialog` selectors. Give those browser dialogs the same restrained shadow and twelve-pixel corners; use eight-pixel corners for appearance groups, theme tiles and selects while retaining their selected checkmarks and keyboard rings. Reduce shelf cover shadows so they do not outweigh titles. Stronger browser selectors account for reader styles loading later. WebKit's native selects rendered at 23 px despite the existing padding; an explicit height of 2.75 rem retains the browser menus and gives them adequate targets that grow with text scaling. No shared native reader stylesheet was edited.

## Design review refinements (October 11, 2026)

The second visual review found three presentation problems in the library: tablet search competed with the brand and actions, Snippets did not share the rail's count alignment, and the embedded catalog added nested cards that did not align with the import area. At 200% text, the toolbar could overlap even when the page reported zero horizontal overflow.

The tablet toolbar now keeps the title and actions on its first row, with a full-width search row below. A named inline container reflows those controls when the available width falls below 28 rem. The browser rail is capped at 40 vw when enlarged text would otherwise consume most of a tablet; labels wrap to two lines, and labels without counts use the remaining row width. Snippets keeps its native link while sharing the rail's layout, hover and keyboard-focus rules. The entire empty state uses a 48 rem maximum width, intrinsic import/connection columns, and a catalog with plain rows and separators.

A separate existing notes regression reproduced a real dismissal problem at 320 × 320 and 200% text: focusing an action scrolled the outer sheet by 24 px and moved the Close target to y = −4 px. A browser-only rule prevents that outer sheet from scrolling while retaining its existing inner content scroller. The original viewport bounds, pointer-hit, saved-passage, remove-action, keyboard-dismissal and focus-restoration assertions remain intact and pass in Chromium and WebKit. This does not alter the Editor's Picks dialog owned by PR262.

Active browser assertions now reflect the intended eight-pixel action corners, twelve-pixel import panels, new import labels, disclosure, tablet search row and twenty-pixel toolbar glyphs. Hit-target requirements remain separate from glyph size. Action checks still cover contrast of at least 4.5:1, hover distinction, stable geometry, keyboard disclosure access and actual file choosers/import. Transparent link contrast is measured over the actual ancestor surfaces.
